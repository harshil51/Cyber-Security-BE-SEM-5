1. Proxy Server 
Definition 

=== PAGE 2 ===
A proxy server is an intermediary computer/server that receives requests from a client and 
forwards those requests to the destination server. 
Instead of: 
User → Internet Server 
the communication becomes: 
User → Proxy Server → Internet Server 
The destination server generally sees the proxy's IP address rather than directly seeing the 
client's IP address. 
Basic Architecture 
             Request 
User ───────────────────► Proxy 
                            │ 
                            │ Request 
                            ▼ 
                       Web Server 
                            │ 
                            │ Response 
                            ▼ 
User ◄────────────────── Proxy 
 
Functions of Proxy Servers 
1. IP masking 
A proxy can hide the client's original IP address from the destination server. 
2. Access control 
Organizations can control which websites or services users can access. 
3. Caching 
Frequently requested resources can be cached to reduce bandwidth usage. 

=== PAGE 3 ===
4. Monitoring 
Organizations can monitor network traffic passing through the proxy. 
5. Content filtering 
Malicious or inappropriate websites can be blocked. 
6. Security 
A proxy can act as an additional security layer between users and the Internet.

3. Types of Proxy Servers 
This is an important exam question. 
1. Forward Proxy 
A forward proxy represents the client. 
Client → Forward Proxy → Internet 
It is commonly used by organizations to control employee Internet access. 
Uses 
• Content filtering 
• Caching 
• Monitoring 

=== PAGE 5 ===
• Access control 
 
2. Reverse Proxy 
A reverse proxy represents the server. 
Internet → Reverse Proxy → Web Server 
It is commonly used by websites and applications. 
Uses 
• Load balancing 
• Web security 
• SSL/TLS termination 
• Hiding backend infrastructure 
• DDoS protection 
 
3. Transparent Proxy 
A transparent proxy forwards traffic while generally requiring little or no client-side 
configuration. 
It is commonly used for: 
• Network monitoring 
• Content filtering 
• Caching 
 
4. Anonymous Proxy 
An anonymous proxy attempts to hide the client's IP address from the destination. 
 
5. High-Anonymity Proxy 
A high-anonymity proxy provides stronger separation between the client and destination and 
may avoid revealing identifying proxy information. 

=== PAGE 6 ===
 
6. Open Proxy 
An open proxy is a proxy accessible by users outside the organization operating it. 
Open proxies can be abused by attackers to obscure the source of traffic. 
 
4. Proxy-Based Cybercrime 
Attackers may abuse proxy infrastructure to make malicious traffic harder to associate with their 
original connection. 
General concept 
Attacker 
   ↓ 
Proxy 1 
   ↓ 
Proxy 2 
   ↓

This is sometimes called proxy chaining. 
Why criminals use proxies 
• Hide source IP 
• Make attribution more difficult 
• Bypass network restrictions 
• Distribute malicious traffic 
• Conduct reconnaissance 
• Access services from different network locations

Other information may still reveal the source, such as:

• Timing information 
• DNS information 
• Application logs 
• Proxy logs 
• Payment records 
• Operational mistakes

6. Anonymizers 
Definition 
An anonymizer is a technology designed to reduce the ability of websites or network observers 
to directly associate online activity with a user's original network identity. 
Examples include: 
• Proxy services 

=== PAGE 9 ===
• VPNs 
• Tor 
• Privacy-oriented relay systems 
Basic idea 
Normal: 
 
User → Website 
  ↓ 
Website sees user's IP 
 
 
Anonymized: 
 
User → Anonymizer → Website 
                    ↓ 
              Sees intermediary 
 
Types of Anonymizers 
1. Proxy-based anonymizer 
Uses an intermediary server. 
2. VPN 
Creates an encrypted connection between the user and VPN infrastructure. 
3. Tor 
Routes traffic through multiple volunteer-operated relays. 
4. Multi-hop systems 
Traffic passes through multiple intermediary systems. 

=== PAGE 10 ===
 
7. Technical Functions of Anonymizers 
Anonymizers generally provide some combination of: 
1. Identity separation 
The destination may see the intermediary rather than the original IP . 
2. Traffic routing 
Traffic is forwarded through intermediary systems. 
3. Encryption 
Some anonymization systems encrypt traffic between selected network points. 
4. Location masking 
The destination may see the intermediary's network location rather than the user's. 
5. Traffic separation 
Multi-hop systems attempt to prevent a single intermediary from learning the complete 
communication relationship. 
 
8. Tor Network Architecture 
Tor = The Onion Router. 
Tor is a distributed anonymity network designed to make traffic analysis and direct source 
identification more difficult. 
Why "onion"? 
The communication is protected through multiple layers, similar conceptually to layers of an 
onion. 
Basic architecture 
                 TOR NETWORK 
 
User 
 │ 

=== PAGE 11 ===
 ▼

 │ 
 ▼ 
Middle Relay 
 │ 
 ▼ 
Exit Relay 
 │

Internet 
 │

Working of Tor 
Suppose a user wants to visit a website. 
Step 1 – Entry relay 
The user's Tor client connects to an entry/guard relay. 
Step 2 – Middle relay 
Traffic passes through another relay. 
Step 3 – Exit relay 
Traffic leaves the Tor network through an exit relay. 
Step 4 – Destination 
The destination website receives the connection from the exit relay. 
 

=== PAGE 12 ===
Onion Routing 
Conceptually: 
Layer 1 → Entry relay 
Layer 2 → Middle relay 
Layer 3 → Exit relay 
Each relay has limited knowledge of the complete path. 
Important components 
Component Function 
Tor Client Runs on user's system 
Guard/Entry Relay First Tor relay 
Middle Relay Intermediate forwarding 
Exit Relay Connects toward normal Internet 
Directory System Helps clients learn relay information 
 
Advantages of Tor 
• Privacy 
• Resistance to some forms of traffic analysis 
• Hides user's IP from destination websites 
• Helps users access information privately 
Limitations 
• Slower than normal browsing 
• Exit traffic may be monitored by destination-side observers 
• Does not guarantee perfect anonymity 
• Endpoint/application leaks can still identify users 
• Misconfiguration can expose information

9. Operation Bayonet 
Operation Bayonet was a major international law-enforcement operation involving the 
takedown of major dark-web marketplaces. 
Two major marketplaces involved were: 
• AlphaBay 
• Hansa Market 
The operation demonstrated international cooperation against illegal activities conducted 
through dark-web marketplaces. 
 
AlphaBay 
AlphaBay was a large dark-web marketplace that facilitated illegal transactions. 
It was taken down in 2017 as part of international law-enforcement efforts. 
 
Hansa 
Hansa was another major dark-web marketplace. 
Law enforcement did something particularly significant with Hansa: after taking control of the 
marketplace, investigators were able to observe activity and gather evidence before the service 
was ultimately shut down. 
 
Importance of Operation Bayonet 
It demonstrated: 
1. International law-enforcement cooperation 
2. Investigation of dark-web infrastructure 
3. Importance of digital evidence 
4. Cryptocurrency tracing and financial investigation 
5. Operational-security weaknesses 

=== PAGE 14 ===
6. Importance of server and infrastructure seizure 
Exam conclusion 
Operation Bayonet demonstrated that anonymity technologies and dark-web marketplaces do 
not guarantee immunity from investigation. Traditional investigation, digital forensics, 
infrastructure analysis and international cooperation can collectively identify and disrupt 
cybercriminal operations. 
 
10. Phishing 
Definition 
Phishing is a social-engineering attack in which an attacker attempts to trick a victim into 
revealing sensitive information or performing an unwanted action by pretending to be a trusted 
person, organization or service. 
Examples of targeted information: 
• Username 
• Password 
• OTP 
• Banking information 
• Personal information 
• Authentication tokens

Step 1 – Target Selection 
Attacker chooses individuals or organizations. 
Step 2 – Information Gathering 
Publicly available information may be used to make fraudulent communication appear

Attacker prepares a deceptive message or fake communication channel. 
Step 4 – Delivery 
The message may be delivered through: 
• Email 
• SMS

The victim may click a link, open an attachment or respond.

The victim may unknowingly submit sensitive information. 
Step 7 – Abuse 
Stolen information may be used for: 
• Account takeover 
• Fraud 
• Identity theft 
• Further attacks 
Step 8 – Concealment 
Attackers may attempt to hide or delete evidence. 
 
12. Types of Phishing 
1. Email Phishing 
Fraudulent emails impersonate legitimate organizations. 
 
2. Spear Phishing 
A targeted phishing attack directed toward a specific person or organization. 
Example 
Instead of sending a generic email to thousands of people, an attacker creates a message 
specifically designed for an employee. 
 
3. Whaling 
Phishing directed toward high-level individuals such as executives. 
Employee → Spear Phishing 
Executive → Whaling 
 

=== PAGE 17 ===
4. Smishing 
Phishing through SMS or text messages. 
SMS + Phishing = Smishing 
 
5. Vishing 
Phishing through voice calls. 
Voice + Phishing = Vishing 
 
6. Clone Phishing 
A legitimate-looking message or website is copied and modified to deceive users. 
 
13. Advanced Phishing Techniques 
Modern phishing may combine social engineering with technical deception. 
1. Social engineering 
The attacker manipulates the victim psychologically. 
Common principles: 
• Urgency 
• Fear 
• Authority 
• Curiosity

• Trust 
 
2. Website impersonation 
Attackers create websites that visually resemble legitimate services. 
 

=== PAGE 18 ===

14. Password Cracking 
Definition 
Password cracking refers to techniques used to recover or guess passwords, usually by testing 
possible password values. 
In authorized security testing, password auditing is used to evaluate password strength. 
 
15. Password Cracking Methods 
1. Brute Force 
Attempts possible combinations systematically. 
Conceptually: 
0000 
0001 
0002 
... 
9999 
For longer passwords, the number of possibilities becomes extremely large. 
Disadvantage 
Very time-consuming for strong passwords. 
 
2. Dictionary Attack 
Uses a list of likely passwords or words. 
For example: 
password 
admin 
welcome 

=== PAGE 20 ===
qwerty 
... 
It is effective against weak, predictable passwords. 
 
3. Hybrid Attack 
Combines dictionary words with common modifications. 
Conceptually: 
password 
password1 
password123 
Password1 
 
4. Credential Stuffing 
Attackers use previously leaked username/password combinations against other services. 
This works because some users reuse passwords. 
 
5. Password Spraying 
Instead of trying many passwords against one account, an attacker tries a small number of 
commonly used passwords across many accounts. 
This can help evade some account-lockout policies. 
 
6. Rainbow Tables 
Precomputed data structures can be used against certain unsalted password hashes. 
Modern systems can reduce this risk using salting and strong password hashing. 
 
16. Popular Password-Cracking/Auditing Tools

Important 
These tools have legitimate penetration-testing and password-auditing applications, but

17. Password Hashing 
A hash function converts input into a fixed-length representation. 
Password 
   ↓ 
Hash Function 
   ↓ 
Hash 
A properly designed password-storage system does not store passwords directly. 
 
18. Types of Password Hashes and Relative Security 
Hash/Method General Security Context 
MD5 Obsolete for password storage 
SHA-1 Obsolete for password storage 
SHA-256 alone Not designed specifically for password storage 
bcrypt Designed for password hashing 

=== PAGE 22 ===
Hash/Method General Security Context 
scrypt Memory-hard password hashing 
Argon2 Modern password hashing approach 
Salted password hash Stronger against precomputed attacks 
Why MD5/SHA-1 are unsuitable for passwords 
They are designed to be computationally fast. 
For password storage, we actually want hashing to be deliberately expensive. 
 
19. Salt 
A salt is a unique random value added to a password before password hashing. 
Password + Unique Salt 
          ↓ 
     Password Hash 
Without salt 
Two users having the same password may have the same hash. 
With unique salts 
User A: 
Password + Salt A → Hash A 
 
User B: 
Password + Salt B → Hash B 
Even if both passwords are identical, their stored hashes differ. 
 
20. Keylogger 
Definition 

=== PAGE 23 ===
A keylogger is software or hardware capable of recording keystrokes. 
It may be used legitimately in controlled environments, but malicious keyloggers can steal 
sensitive information. 
Information potentially captured 
• Usernames 
• Passwords 
• Messages 
• Search terms 
• Financial information 
 
21. Types of Keyloggers 
1. Software Keylogger 
Installed as malicious or unauthorized software. 
 
2. Hardware Keylogger 
A physical device placed between a keyboard and computer, or implemented within hardware. 
 
3. Kernel-Level Keylogger 
Operates at a low level of the operating system and can be difficult to detect. 
 
4. Browser-Based/Script-Based Logging 
Some malicious scripts can capture user input within web applications.
